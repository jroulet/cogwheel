## Build 1 of the microlensing program: port the research-grade Chang–Refsdal prototype (.claude/spec/lensing_paper/code/) into a cogwheel-grade lens engine under cogwheel/lensing/chang_refsdal/ — geometry, contour-free amplification operator, and the topology-stable 4-channel decomposition F(w)=sum_a e^{iw tau_a} K_a(w) — with tolerance-based accuracy tests as the build gate.

ASSUMPTIONS AND BRIEF CORRECTIONS (documented per instructions; three of the brief's hard requirements are factually wrong and this plan deliberately deviates):

(1) THE SUBPACKAGE IS NOT NEW. cogwheel/lensing/__init__.py, chang_refsdal/__init__.py and chang_refsdal/_dd.py ALREADY EXIST. _dd.py is a tested (cogwheel/tests/test_lensing_dd.py), numba-shaped double-double real+complex arithmetic module landed by an earlier build. Build 1 CONSUMES it; it must not be rewritten. Only geometry.py / _hyp1f1.py / operator.py / channels.py are new.

(2) 'Production paths: numpy double precision' (hard req 2) is WRONG AS STATED and must carve out the 1F1 kernel. The operator's cancellation exponent L = w*(|y'| + gamma'/2) = w*dtau/2 splits into TWO INDEPENDENT channels at TWO SEPARATE CODE SITES: L_1F1 = w*|y'| (inside the 1F1 Maclaurin series) and L_op = w*gamma'/2 (the shear-series accumulation). Float64 (eps=2.2e-16) crosses the brief's own 1e-10 gate at L=13. L_op <= 6 over the whole certified domain, so the operator series, the prefactor C(w), the D_beta^n representation evaluation and ALL geometry are provably fine in float64 — the prototype empirically confirms this (it casts its mpmath G^(k) to complex128 and still measures 4.7e-16 over w in [5,40]). But L_1F1 = w*|y'| exceeds 13 for the 2-image regime at Y>=0.5, w=40 — which is the null-hypothesis bulk of every microlensing posterior, not a corner case. Therefore dd enters ONLY the 1F1 kernel (value + Maclaurin + k-ladder). This makes the build SMALLER than a blanket-dd reading, not larger. Also: drop 'Kummer transform' from the precision story — z = -i*w*s/2 is purely imaginary so |e^z|=1 and Kummer moves no magnitude.

(3) 'The high-w regime should short-circuit to stationary-phase kernels via the switch machinery' (hard req 2) is FALSE about the prototype and unachievable at 1e-10. The prototype calls _operator_total UNCONDITIONALLY at every w; the switch S_j (rho0=0.5, rho1=4) only distributes the cluster's exact field among channels — it is a smoothness/topology device that injects NO error into the total, not an accuracy short-circuit. A real short-circuit means truncating the residual R to zero, which costs |R| ~ (w*dtau)^-3 — that is 1.6e-2 at w*dtau=4. This plan instead adds an EXPLICIT, separately-gated R-truncation knob (W_cut, default 100 => |R| ~ 1e-6 => dlnL ~ 5e-9 at SNR 100). Note the truncation threshold and dd's ceiling coincide by construction (both are L = w*dtau/2 ~ 50), so there is NO band where the operator is needed and beyond dd.

(4) 'Exact reconstruction <= 1e-12 relative everywhere' (hard req 1b) is UNACHIEVABLE NEAR FOLDS by construction. The identity is algebraic and exact; the only error is roundoff relative to the largest intermediate, max_a|K_hat_a| ~ sqrt|mu_a|, which diverges at critical points — not relative to |F_op| ~ 1. This is why the prototype's own tests assert 2e-14 for the cluster-local topology-stable builders but only 3e-13/2e-12 for the global tracker: that gap is a REAL algorithmic property, not sloppiness. Gate on a scale-aware bound C*eps*(|F_op| + sum_a|K_hat_a| + |R|) with C=100, PLUS frozen absolute backstops at the prototype's demonstrated configs to catch regressions.

(5) The quartic validation CSV's 168 rows are ALL kind='general' (verified directly by regex — an exploration agent claimed fold/cusp rows exist; it hallucinated). It provides ZERO axial/degenerate coverage even though the brief requires those branches. n_multistart is a frozen answer from a solver that no longer exists in the prototype — that makes it a genuinely independent, non-drifting oracle for image COUNT, which is the right thing to assert; matched_position_error is a cross-method quantity that cannot be recomputed and must NOT be asserted on. The degenerate/axial branch is instead covered by the exact y=0 analytic solution.

(6) chang_refsdal_exact_partition.py is SUPERSEDED and imported by nothing — not even its own tests. It is NOT ported. Its interpolation functions are Build 2's job per the brief.

(7) mpmath is NOT a declared dependency, yet cogwheel/tests/test_lensing_dd.py imports it at top level — the suite already fails to collect on a clean install. WP6 fixes this via a test extra.

WHERE DD IS MANDATORY (Professor, quantitative): the 1F1 Maclaurin series in z = -i*w*s/2 — BOTH the terms and their summation must be dd. Compensated/Kahan summation does NOT rescue this: its bound still carries sum|term_i|, and the terms themselves are exponentially larger than the result (max term ~ e^{w*Y} at k* = w*Y/2). Also dd the Pochhammer/base^k ladder that builds G^(k), since it feeds the Maclaurin at the same precision.

WHERE FLOAT64 IS PROVABLY FINE: the prefactor C(w) = exp[pi*w/4 + (i*w/2)*ln(w/2)]*Gamma(1 - i*w/2). It is a COMMON multiplicative factor across all k and all n, so its relative error factors out of the sum exactly and contributes ~1e-16 flat, unamplified. Do NOT dd it.

TWO FLOAT64 TRAPS IN C(w), both mandatory to handle: (a) exp(pi*w/4) OVERFLOWS at w~900 while Gamma(1 - i*w/2) underflows like e^{-pi*w/4} — compute via complex loggamma and combine exponents ANALYTICALLY; never evaluate exp(...)*gamma(...) as written. (b) The (w/2)*ln(w/2) phase cancels against Im loggamma(1 - i*w/2) — cancel it analytically, not numerically.

DO NOT implement a Kummer transform for precision reasons: z is purely imaginary so |e^z| = 1 and Kummer moves no magnitude. Both Kummer forms have identical max term e^{w*Y}. (Kummer's only legitimate role is the once-only upstream step from F_PM to G_PM.)

K-LADDER STABILITY — a genuine trap: the prototype calls mp.hyp1f1 once per k (k=0..~84) and ladders ONLY the Pochhammer prefactor; it does NOT recur the 1F1 itself. If you k-ladder the 1F1 via contiguous relations to save evaluations (the obvious speed win), be aware forward recurrence for 1F1(a+k; 1+k; z) is frequently UNSTABLE — the minimal solution gets swamped. Test it (see verification); if forward recurrence fails, use Miller's backward recurrence. The evaluation count must scale O(max_order), not O(max_order^2).

EXPONENT-RANGE CAVEAT (missing from _dd.py's docstring): dd extends the MANTISSA, not the EXPONENT. hi is a float64, so overflow is still 1.8e308 and the low word is silently lost near denormals. |G^(k)| reaches ~1e92 at w=40, k=84 and OVERFLOWS at w ~ 700 with max_order=42. Gate the input w with a clear error above the certified ceiling rather than returning silent garbage.

numba-SHAPED but DEFER @njit (the brief permits this and the Simplifier explicitly warns against premature application): plain loops, plain arrays, no closures, no containers, homogeneous scalar returns, no object mode. Document the intended hot path in the module docstring. Only add @numba.njit(cache=True) if WP3's performance gate fails without it. Note pylint's ignored-modules does not include numba.

ALSO FIX _dd.py's DOCSTRING (WHY section is mis-scoped — it implies the whole pipeline needs dd): it should state that L_1F1 = w*|y'| and L_op = w*gamma'/2 are INDEPENDENT channels at SEPARATE code sites; that dd is required only for the former; that dd's ceiling (w*Y <= 60 at 1e-6) exists precisely to close the gap to the stationary-phase branch's onset (w*Y >= 50), which float64 (w*Y <= 22) cannot bridge; and add the mantissa-not-exponent caveat above. Change the docstring ONLY — the arithmetic code is correct and its tests must keep passing unchanged.
